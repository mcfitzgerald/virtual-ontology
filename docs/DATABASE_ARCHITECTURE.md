# Virtual Twin Database Architecture

## Overview
The Virtual Twin system uses a single SQLite database (`data/mes_database.db`) containing 17 tables with approximately 288,000 records total. The database integrates historical manufacturing data with simulation results, optimization outputs, and recommendation tracking.

## Database Location
- **Primary Database:** `data/mes_database.db`
- **Initialization Script:** `scripts/init_twin_database.py`
- **Note:** Previously had an orphan `manufacturing.db` in root (now removed)

## Table Categories & Structure

### 1. Core Manufacturing Data (Historical)

#### **mes_data** (36,288 records)
Primary historical data from Manufacturing Execution System
```sql
CREATE TABLE mes_data (
    id INTEGER PRIMARY KEY,
    timestamp DATETIME NOT NULL,
    production_order_id VARCHAR,
    line_id VARCHAR NOT NULL,
    equipment_id VARCHAR NOT NULL,
    equipment_type VARCHAR NOT NULL,
    product_id VARCHAR,
    product_name VARCHAR,
    machine_status VARCHAR NOT NULL,
    downtime_reason VARCHAR,
    good_units_produced INTEGER NOT NULL,
    scrap_units_produced INTEGER NOT NULL,
    target_rate_units_per_5min INTEGER NOT NULL,
    standard_cost_per_unit FLOAT NOT NULL,
    sale_price_per_unit FLOAT NOT NULL,
    availability_score FLOAT NOT NULL,
    performance_score FLOAT NOT NULL,
    quality_score FLOAT NOT NULL,
    oee_score FLOAT NOT NULL,
    energy_consumption_kwh REAL
);
```
- **Indexes:** timestamp, production_order_id, equipment_id, product_id, line_id, oee_score
- **Accessed by:** API server, SQL queries, baseline calculations
- **Purpose:** Historical production metrics for analysis

### 2. Virtual Twin Simulation Tables

#### **twin_runs** (36 records)
Simulation run metadata with full provenance tracking
```sql
CREATE TABLE twin_runs (
    run_id TEXT PRIMARY KEY,
    run_type TEXT,  -- baseline, simulation, recommendation
    seed INTEGER,
    generator_version TEXT,
    parent_run_id TEXT,
    started_at TIMESTAMP,
    finished_at TIMESTAMP,
    config_delta_json TEXT,
    data_hash TEXT,
    output_path TEXT,
    kpi_summary_json TEXT,
    notes TEXT,
    status TEXT  -- pending, running, completed, failed
);
```
- **Accessed by:** SimulationRunner, OptimizationEngine, GraphQL API
- **Purpose:** Complete audit trail of all simulations

#### **simulation_data** (235,872 records)
Synthetic data generated by simulations
```sql
CREATE TABLE simulation_data (
    id INTEGER PRIMARY KEY,
    run_id TEXT NOT NULL,
    timestamp DATETIME NOT NULL,
    production_order_id VARCHAR,
    line_id VARCHAR NOT NULL,
    equipment_id VARCHAR NOT NULL,
    -- Similar structure to mes_data
    FOREIGN KEY (run_id) REFERENCES twin_runs(run_id)
);
```
- **Accessed by:** SimulationRunner, analysis tools
- **Purpose:** Store simulation outputs for comparison

#### **twin_state** (3 records)
Current virtual twin configuration state
```sql
CREATE TABLE twin_state (
    state_id INTEGER PRIMARY KEY,
    timestamp TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    current_run_id TEXT,
    baseline_run_id TEXT,
    parameters_json TEXT NOT NULL,
    active_recommendations_json TEXT,
    notes TEXT,
    FOREIGN KEY (current_run_id) REFERENCES twin_runs(run_id),
    FOREIGN KEY (baseline_run_id) REFERENCES twin_runs(run_id)
);
```
- **Accessed by:** TwinStateManager, RecommendationEngine
- **Purpose:** Track active configuration and baselines

#### **parameter_history** (30 records)
Parameter change tracking for audit
```sql
CREATE TABLE parameter_history (
    change_id INTEGER PRIMARY KEY AUTOINCREMENT,
    run_id TEXT NOT NULL,
    timestamp TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    parameter_name TEXT NOT NULL,
    old_value REAL,
    new_value REAL NOT NULL,
    change_reason TEXT,
    applied_by TEXT,
    FOREIGN KEY (run_id) REFERENCES twin_runs(run_id)
);
```
- **Accessed by:** SimulationRunner, audit tools
- **Purpose:** Track parameter evolution over time

### 3. Optimization & Intelligence Tables

#### **optimization_results** (0 records - ready for use)
Pareto-optimal solutions from optimization runs
```sql
CREATE TABLE optimization_results (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    run_id TEXT NOT NULL,
    generation INTEGER NOT NULL,
    solution_index INTEGER NOT NULL,
    objectives_json TEXT NOT NULL,
    parameters_json TEXT NOT NULL,
    constraints_satisfied BOOLEAN DEFAULT 1,
    is_pareto BOOLEAN DEFAULT 0,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (run_id) REFERENCES twin_runs(run_id)
);
```
- **Accessed by:** OptimizationEngine
- **Purpose:** Store multi-objective optimization results

#### **recommendations** (10 records)
AI-generated improvement suggestions
```sql
CREATE TABLE recommendations (
    recommendation_id INTEGER PRIMARY KEY AUTOINCREMENT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    run_id TEXT,
    recommendation_type TEXT,
    parameters_json TEXT NOT NULL,
    expected_improvement_json TEXT,
    confidence REAL,
    status TEXT CHECK(status IN ('pending', 'accepted', 'rejected', 'implemented')),
    notes TEXT,
    FOREIGN KEY (run_id) REFERENCES twin_runs(run_id)
);
```
- **Accessed by:** RecommendationEngine
- **Purpose:** Track and manage improvement recommendations

#### **confidence_tracking** (2 records)
Statistical confidence metrics for KPIs
```sql
CREATE TABLE confidence_tracking (
    tracking_id INTEGER PRIMARY KEY AUTOINCREMENT,
    run_id TEXT NOT NULL,
    kpi TEXT NOT NULL,
    mean_value REAL NOT NULL,
    std_dev REAL NOT NULL,
    confidence_95_lower REAL,
    confidence_95_upper REAL,
    sample_size INTEGER,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (run_id) REFERENCES twin_runs(run_id)
);
```
- **Accessed by:** Analysis tools
- **Purpose:** Track uncertainty in predictions

## Database Indexes

### Performance Indexes
- `ix_mes_data_timestamp` - Time-based queries
- `ix_mes_data_equipment_id` - Equipment analysis
- `ix_mes_data_oee_score` - OEE ranking queries
- `ix_mes_data_product_id` - Product-based analysis
- `ix_mes_data_line_id` - Line performance
- `ix_simulation_run_timestamp` - Simulation timeline

## Data Volumes & Growth

### Current State (Dec 2024)
- **Total Records:** ~288,000
- **Database Size:** ~50MB
- **Growth Rate:** ~20,000 records per simulation run

### Retention Strategy
- **Historical Data (mes_data):** Permanent
- **Simulation Data:** Keep last 100 runs
- **Optimization Results:** Keep Pareto-optimal only
- **Logs:** 90-day retention

## Migration & Backup

### Backup Strategy
```bash
# Daily backup
sqlite3 data/mes_database.db ".backup data/backups/mes_database_$(date +%Y%m%d).db"
```

### Migration Path
1. All components use `data/mes_database.db`
2. SimulationRunner defaults to this path
3. No hardcoded paths in production code

## Security Considerations

- **Read-Only API:** SQL endpoint restricted to SELECT
- **Parameterized Queries:** Prevent SQL injection
- **Audit Trail:** All changes tracked in parameter_history
- **Provenance:** PROV-O compliant tracking ready
