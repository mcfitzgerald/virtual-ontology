# Database and API Documentation

## Overview

The Virtual Twin system uses a SQLite database (`data/mes_database.db`) with 18 tables containing manufacturing data, simulation results, and configuration management. The FastAPI server provides SQL query access and database management endpoints.

## Database Architecture

### Database Location
- **Primary Database:** `data/mes_database.db` (~87MB)
- **Total Records:** ~290,000 across 18 tables
- **Connection:** SQLite3 with proper transaction handling

### Table Structure

#### Core Manufacturing Data

**mes_data** (2,592 records)
Primary historical data from Manufacturing Execution System
```sql
CREATE TABLE mes_data (
    id INTEGER PRIMARY KEY,
    timestamp DATETIME NOT NULL,
    production_order_id VARCHAR,
    line_id VARCHAR NOT NULL,
    equipment_id VARCHAR NOT NULL,
    equipment_type VARCHAR NOT NULL,
    product_id VARCHAR,
    product_name VARCHAR,
    machine_status VARCHAR NOT NULL,
    downtime_reason VARCHAR,
    good_units_produced INTEGER NOT NULL,
    scrap_units_produced INTEGER NOT NULL,
    target_rate_units_per_5min INTEGER NOT NULL,
    standard_cost_per_unit FLOAT NOT NULL,
    sale_price_per_unit FLOAT NOT NULL,
    availability_score FLOAT NOT NULL,
    performance_score FLOAT NOT NULL,
    quality_score FLOAT NOT NULL,
    oee_score FLOAT NOT NULL,
    energy_consumption_kwh REAL
);
```

#### Virtual Twin Tables

**twin_runs** (36 records)
Simulation run metadata and lineage tracking
```sql
CREATE TABLE twin_runs (
    run_id TEXT PRIMARY KEY,
    run_type TEXT,  -- baseline, simulation, optimization
    seed INTEGER,
    generator_version TEXT,
    parent_run_id TEXT,
    started_at TIMESTAMP,
    finished_at TIMESTAMP,
    config_delta_json TEXT,
    data_hash TEXT,
    output_path TEXT,
    kpi_summary_json TEXT,
    notes TEXT,
    status TEXT  -- pending, running, completed, failed
);
```

**simulation_configs** (1 record)
Configuration storage with deduplication
```sql
CREATE TABLE simulation_configs (
    config_id TEXT PRIMARY KEY,
    run_id TEXT,
    config_type TEXT,  -- full, delta, base
    config_json TEXT NOT NULL,
    config_hash TEXT UNIQUE,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    description TEXT,
    is_archived BOOLEAN DEFAULT 0,
    FOREIGN KEY (run_id) REFERENCES twin_runs(run_id)
);
```

**twin_state** (3 records)
Current virtual twin configuration state
```sql
CREATE TABLE twin_state (
    state_id INTEGER PRIMARY KEY,
    timestamp TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    current_run_id TEXT,
    baseline_run_id TEXT,
    parameters_json TEXT NOT NULL,
    active_recommendations_json TEXT,
    notes TEXT
);
```

**parameter_history** (30 records)
Audit trail of parameter changes
```sql
CREATE TABLE parameter_history (
    change_id INTEGER PRIMARY KEY AUTOINCREMENT,
    run_id TEXT NOT NULL,
    timestamp TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    parameter_name TEXT NOT NULL,
    old_value REAL,
    new_value REAL NOT NULL,
    change_reason TEXT,
    applied_by TEXT
);
```

## API Endpoints

### Base URL
`http://localhost:8000`

### Core Endpoints

#### SQL Query Execution
`POST /query`

Execute read-only SQL queries against the database.

Request:
```json
{
  "sql": "SELECT * FROM mes_data WHERE oee_score > 0.8",
  "limit": 1000
}
```

Response:
```json
{
  "query": "SELECT * FROM mes_data WHERE oee_score > 0.8",
  "columns": ["id", "timestamp", "line_id", ...],
  "data": [...],
  "row_count": 42,
  "limited": false
}
```

### Database Management Endpoints

#### Database Statistics
`GET /api/database/stats`

Returns comprehensive database statistics.

Response:
```json
{
  "database_path": "/path/to/mes_database.db",
  "file_size_mb": 87.54,
  "total_tables": 18,
  "total_records": 290000,
  "tables": {
    "mes_data": 2592,
    "twin_runs": 36,
    ...
  }
}
```

#### Table Information
`GET /api/database/tables`

Query parameters:
- `include_sample`: Include sample data (default: false)
- `limit`: Number of sample rows (default: 5)

#### Configuration Management
`GET /api/database/configs`

List all simulation configurations with metadata.

`GET /api/database/config/{config_id}`

Retrieve specific configuration JSON.

#### Database Health Check
`GET /api/database/health`

Performs integrity checks and reports issues.

Response:
```json
{
  "status": "healthy",  // or "warning", "unhealthy"
  "issues": [],
  "warnings": []
}
```

#### Selective Cleanup
`POST /api/database/cleanup`

Safely clean non-critical data.

Request:
```json
{
  "category": "logs",  // Options: logs, simulation, optimization
  "tables": ["sync_health_log"],
  "older_than_days": 7,
  "preserve": ["twin_runs"]
}
```

### Simulation Endpoints

#### Run Simulation
`POST /api/simulation/run`

Execute simulation with actionable parameters.

#### Get Recommendations
`GET /api/simulation/recommendations`

Retrieve AI-generated optimization recommendations.

## Configuration Management

### Storage Architecture

Configurations are stored in the `simulation_configs` table with:
- **Automatic deduplication** using SHA256 content hash
- **Type classification**: full, delta, or base configurations
- **Run linkage**: Each config linked to its simulation run
- **Soft delete**: Archived configs retained but marked

### Configuration Types

**Full Configuration** (~16KB)
Complete simulation setup including all parameters, equipment definitions, and anomaly patterns.

**Delta Configuration** (small)
Only changed parameters from baseline:
```json
{
  "micro_stop_probability": 0.15,
  "performance_factor": 0.85,
  "scrap_multiplier": 2.0
}
```

**Base Configuration**
Original `mes_data_config.json` foundation.

### Usage Patterns

#### Store Configuration
```python
from twin.config_manager import ConfigurationManager

config_mgr = ConfigurationManager()
config_id = config_mgr.store_config(
    config_dict,
    run_id="sim-123",
    config_type="full",
    description="Optimized for energy reduction"
)
```

#### Retrieve Configuration
```python
# Get specific config
config = config_mgr.get_config(config_id)

# List recent configs
configs = config_mgr.list_configs(limit=10)

# Get config for a run
config = config_mgr.get_config_by_run("sim-20250809-123456")
```

#### Query Configurations
```sql
-- Find configs with specific parameter values
SELECT config_id, 
       json_extract(config_json, '$.twin_metadata.parameters_applied.micro_stop_probability') as micro_stop
FROM simulation_configs
WHERE json_extract(config_json, '$.twin_metadata.parameters_applied.micro_stop_probability') < 0.2;
```

## Technical Reference

### Connection Handling
All database operations use proper transaction handling:
```python
with sqlite3.connect(db_path) as conn:
    cursor = conn.cursor()
    # Operations here
    conn.commit()  # If modifying data
```

### Safety Features
- **Read-only queries**: `/query` endpoint restricted to SELECT statements
- **Protected tables**: Core data tables cannot be cleaned via API
- **Transaction safety**: All modifications use transactions
- **Validation**: Input validation on all endpoints

### Error Handling
- **200**: Success
- **400**: Bad request (invalid parameters)
- **404**: Resource not found
- **500**: Internal server error

### Component Access Matrix

| Component | Primary Tables | Secondary Tables |
|-----------|---------------|------------------|

| OptimizationEngine | optimization_results | twin_runs |

| TwinStateManager | twin_state | twin_runs |

## Maintenance

### Database Backup
```bash
# Daily backup
sqlite3 data/mes_database.db ".backup data/backups/mes_$(date +%Y%m%d).db"
```

### Archive Old Configurations
```python
config_mgr = ConfigurationManager()
archived = config_mgr.cleanup_old_configs(days_to_keep=30)
```

### Check Database Size
```sql
SELECT 
    COUNT(*) as total_configs,
    SUM(LENGTH(config_json)) / 1024.0 / 1024.0 as size_mb
FROM simulation_configs
WHERE is_archived = 0;
```

## Best Practices

1. **Use ConfigurationManager** for all config operations
2. **Link configs to runs** for full traceability
3. **Add descriptions** to important configurations
4. **Regular cleanup** of old logs and archived data
5. **Monitor database size** and perform backups
6. **Use parameterized queries** to prevent SQL injection
